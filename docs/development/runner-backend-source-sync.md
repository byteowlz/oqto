# Runner/backend source convergence

The active Oqto source checkouts are Linux `~/byteowlz/oqto_refactor` and Studio
`~/byteowlz/oqto`. Their local `main` refs must identify the same canonical commit.
Studio may stay on its Web/UI branch, but its entire `backend/` Git tree must
match canonical `main`, with no staged, unstaged or untracked backend source.
Mobile remains a separate repository; do not switch or overwrite it to sync Oqto.

Before parallel backend work, and after a cross-machine integration, run:

```sh
python3 -B scripts/dev/check-runner-backend-sync.py \
  --ssh mac --remote-repo '~/byteowlz/oqto'
python3 -B scripts/tests/test-runner-backend-sync.py
```

The read-only check fails on different canonical commits, backend trees, dirty
backend source, SSH failure or invalid responses. It allows a UI-only branch
head to differ. It does **not** establish release readiness, installed binary
identity, feature acceptance, or convergence of historical feature/proof clones.

Preserve bundles, separate index/working patches and untracked files before
reconciliation. Commit source with explicit paths; never include central tracker
migration state, credentials, memory stores or generated bytecode. Import and
review Mac-only backend commits, retain both sides' safety checks, then compare
the complete backend tree—not just the files believed to have changed. Retain
historical feature branches and immutable qualification receipts rather than
silently promoting blocked pilots or rewriting their evidence.

Commit/checkpoint unrelated active agent batches separately. A clean backend
check is not a claim that experimental `tools/oqt` work has stopped changing.
Extension source is independently shared in `~/byteowlz/pi-agent-extensions`;
compare its commit/tree on both machines as part of a TUI-RPC handoff. Updating
source is not deployment, runtime-pin advancement or permission to restart Pi.
