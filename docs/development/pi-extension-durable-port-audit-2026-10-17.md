# Pi extension → oq / Pi Durable port audit

Date: 2026-10-17. Tracker: `oqto-g7rk.4`. **Analysis and recommendations, not implementation or adoption approval.**

## Recommendation

**Port useful capabilities, not the classic ExtensionAPI loader.** Most of this collection has lasting product value, but copying its privileged Node process, session-file assumptions and terminal widgets into the Durable brain would defeat the architecture. Keep classic Pi supported separately. Share semantic schemas, pure reducers/validators and conformance fixtures; place protected operations in the owning host/provider and presentation in each client.

Start with **persistent names/auto-naming, introspection, todos, capability discovery and content selection**. Then scoped history/mmry and draft/export conveniences. Reuse Durable's task/conversation/fork/compaction machinery for the more complex features. Do not import the sudo/SSH/secret execution loops as brain extensions or turn legacy recovery hooks into additional agent loops.

No extension port, user configuration change, deployment, provider call or mobile device execution was performed for this audit.

## Shared integration rules

1. **No compatibility shim that restores ambient privileges.** A classic extension runs with its Pi process's OS permissions. `pi.exec`, `spawn`, slash commands and `user_bash` do not automatically cross the oq guard. The privileged classic loader is not the portable extension interface.
2. **Use native Durable state, not a second session store.** Host metadata for Session names; `defineDoc`/transactional state for conversation features; native task/entry identities for operations. Choose conversation versus Session versus client-local scope and fork behavior explicitly. Permission ledger is authority, not chat history. Hosted history remains oqto-log; hstry is legacy/archive interop.
3. **Preserve all three tool-result channels.** Classic `content` / `details` / `outputSchema + structuredContent` map deliberately to Durable `output` / `details` / `structuredOutputSchema + structuredOutput`, not a blind object cast. Preserve errors, usage, diagnostics, byte limits and omission/paging semantics. Source: upstream `packages/durable/src/harness/types.ts:145-192,282-325`.
4. **Availability is not authorization.** A registered tool, model, UI surface, OS permission, installed CLI or Selection answer cannot mint a grant. Bind principal/Session/workspace/audience, exact arguments, policy revision, expiration and invocation lifetime at the protected operation boundary. Redaction is defense-in-depth, not a substitute for secret-use authorization.
5. **Declare recovery semantics per operation.** Durable defaults tools to unsafe replay. Reads can disclose newly unauthorized data or change between attempts; “read-only” alone is not a recovery contract. Writes/spawns require protected intent/result receipts or explicit uncertainty; external exactly-once behavior requires cooperation from the external service. Cancellation of a wait is not confirmation that its effect stopped.
6. **Separate model disclosure from execution permission.** Naming, memory extraction, summarization and workflow priming may disclose prompts/history to a secondary model. Current model credentials or “cheapest available” are not consent to send local/private content to another provider. No silent local-to-cloud fallback.
7. **Host-neutral semantics, explicit platform adapters.** TUI, Workbench, SwiftUI, Compose and headless clients share request/result schemas. A phone need not run a daemon, shell or UDS listener. Supported/unsupported discovery and OS lifecycle gaps are explicit. Native OS access and the current oq grant must both hold.
8. **Keep source archives passive.** Classic JSONL discovery/import needs explicit origin/identity maps and worker-owned transactions. Upstream's classic loader may append a missing newline; do not use it for read-only archive ingestion. Opening a resumed Durable host is not archive preview. Copied storage cannot authorize a second execution owner.

Existing seams: ADR-0024 and `backend/crates/oqto-runner/src/protocol.rs` describe the remote protocol; ADR-0059/0060 and `backend/crates/oq-permissions/src/{policy,ledger}.rs` describe local protected authority. These do not yet constitute a complete versioned embedded Session/capability/provider SDK. General trusted providers remain proposed (`oqt-providers`); do not call them already implemented.

## Naming: concrete first feature, not a direct file copy

The classic implementation is more than automatic titles:

- `pi-auto-rename/index.ts:1470-1539`: naming from first prompt / agent-end fallback; `:1589-1655`: `rename_session` tool.
- `:371-402`: workspace prefix can execute a shell command. `:803-858,948-970`: direct endpoint is tried before registry generation; `:632-696`: current/cheapest model resolution. None is suitable as ambient mobile/brain privilege.
- `:1380-1403`: classic `setSessionName` plus `oqto_title_changed` status notification; this is not a durable shared title service.
- `tab-title.ts:86-115` and `tab-title-inbound.ts:120-339`: Herdr/tmux ownership, echo suppression and lifecycle fencing are useful **terminal adapter** work, not shared engine state.
- Upstream `packages/coding-agent/src/experimental/session-catalog.ts:1-9,45-77` and `experimental/services/sessions.ts` currently have identity/creation/workspace and create/remove/attach/detach, not a shared title API. Explicit classic Pi naming is a different API.

**Required small design:** stable Session metadata operation and committed `title_changed` revision; `title`, `titleSource`, title revision and an explicit optional readable label. A title never changes the machine ID. Automatic work starts from an admitted, committed input (not an unsent draft or rejected submission), captures that entry identity plus Session identity and title revision, generates asynchronously under approved model/disclosure policy, and commits only if still eligible. Manual title changes win over delayed automatic results; simultaneous clients and reconnects see the same committed title. An agent rename is an explicit scoped metadata mutation, not permission escalation.

`piext-7zse` proves the existing same-Session race: start delayed automatic generation, manually set `Manual Choice`, then release fake `Generated Title`; current implementation overwrites the manual name. Stale-context catches do not solve this race. The port must include a regression mechanism rather than copying the race.

Minimum naming fixtures: no-model deterministic fallback; no network in local-only mode; no automatic extra-provider fallback; one initial auto job per eligible revision; rejected submissions and unsent drafts cause no naming/disclosure; manual/agent edit during generation; Session switch/fork/close; two writers/CAS; restore/reopen; control/ANSI and byte bounds; stable machine IDs and distinct fork labels; no terminal-focused-tab mutation; metadata audience restrictions.

## Conversation state and presentation: reuse semantics, not sidecars

`pi-todolist/index.ts:150-205` stores JSON files, optionally keyed by Session ID; `:247-273` derives a parent ID from a classic session filename and copies a sidecar on fork. This is not a historical branch snapshot. The useful tool schema/reducer and compact presentation can be retained, but new state must have explicit scope and migration semantics. Durable already demonstrates a transactional `Todos` document with `scope`, `history` and `fork` choices in `packages/durable/README.md:583-606`. Pick `initial` / `current` / `asOf` intentionally, with matching history support and regression fixtures; do not infer state from filenames, visible messages or array length.

`pi-prompt-stash/README.md` documents text-only storage, private session/cwd/global scopes, locks, explicit omissions, editor-change fencing and restoration-before-removal. Preserve these useful invariants. Its broader-history picker is deliberately bounded, not a full retrieval engine, and promotion fills an editor rather than automatically submitting or creating executable extension code. A native port must not silently attach files it never stored, restore another Session's private draft or execute leading `/`/`!` content.

RPC UI support is not custom-terminal support: classic `hasUI` can be true in RPC mode. Native pickers/password dialogs need explicit presentation adapters; no headless automatic confirmation or terminal-key injection fallback. Read models and status widgets are disposable projections, not the durable authority for pending forms, todos, queue admission or execution completion.

The mobile/shared replacement must not carry forward this launch route.

Its assistant-text extraction also loses non-text parts. Retire this implementation in favor of reviewed independent context forks; cancel must not initiate inference.
- **Process-wide identity:** `pi-env-ctx` and `pi-oqto-bridge` mutate global environment variables. A multi-Session host needs per-admitted-execution metadata, not one shared mutable identity. Environment/correlation fields are descriptive and spoofable, never grants or durable input acknowledgments.
- **Selection store:** reuse its revision/scope/lifecycle semantics, not its filesystem/lock implementation unmodified. Renderer discovery and host acknowledgment do not authenticate the submitting user; the transport must authorize every read/save/submit. The source has useful CAS/scope/HTTP-protection assertions, but those suites were not executed here.
- **Image budgeting:** upstream Durable's injectable `ImageProcessor` supersedes the deep-import shim; decoder input/memory and aggregate multi-image/provider request budgets still need qualification. A bounded single output is not an aggregate request cap.

Independent session/surface reviewers inspected the older `oqto-durable-support` worktree (`52e49298`) rather than the parent-selected dirty main integration. Their extension/upstream evidence is included; their worktree observations are not proof about the newer main safety fixes. Neither lane ran its proposed conformance tests. Recommendations apply to both native embedded oq hosts and remote-client modes; a phone is **not** required to be remote-only.

## Workflow and recovery: reuse the engine, retain the missing gates

`packages/pi-durable-workflow-core/index.ts` is already a useful portability example: no Pi or Node imports; validation, canonical digest, revision invalidation, review, bounded snapshots/receipts and elapsed interval parsing. Versioned intent can be shared as data/fixtures; Apple/Android must qualify WebCrypto/TextEncoder or provide equivalent implementations. **A matching serialized review object is not an authenticated grant.** Host authority must independently verify the actor, binding, revision and current scope.

`pi-durable-workflow/index.ts:123-194,252-296` restores per-Session proposals, rejects stale dialogs and keeps activation `adapter_unavailable`. `context.ts` captures a bounded **text projection**, not native entry/checkpoint import. `packages/pi-durable-workflow-executor/executor.mjs:42-121,155-209` is an isolated Durable **1.0.4** trusted-host qualification: no tool execution, no production authority/scheduler. It gates actual transport because that version reports hook exceptions rather than treating all hooks as admission vetoes. Do not transplant it into the current pin without conformance review, or infer OS confinement from a timeout/run count.

Pinned Durable provides retries and overflow compaction (`packages/durable/src/harness/generation.ts:455-504`), owned child tasks/conversations and restart policies (`types.ts:233-279,289-290`), and compaction replacement (`types.ts:768-788`). Its `onYield` is a controlled continuation, not an excuse to recreate arbitrary `agent_end` continuation loops. A `stop` with empty content is accepted as an answer at `generation.ts:459-464`; a provider-specific empty-response defect still needs evidence and an explicit policy.

Classic recovery sources explain why they should not be copied: `pi-error-recovery/index.ts:493-532` filters images/error messages and `:533-604` injects new user input; `pi-azure-empty-response-guard/index.ts:240-308` sleeps/injects follow-up or resends text based on ephemeral counters. Keep real provider fixes at the provider layer, bind attempt budgets to stable operation IDs, preserve visible diagnostics and never blindly replay effects. There are no dedicated tests in either active workaround directory in this source snapshot.

## Protected-provider findings that affect port decisions

These are source-backed migration findings, not a complete security assessment of each external service:

- **kyz:** `pi-kyz/index.ts:230-343` overrides bash and user-bash; `:172-213` caches selected/all-tag values; `/kyz-run` at `:489-503` is an alternate direct execution path. Multi-field secret values enter CLI argv (`:150-163`). Keep redaction helpers (`scrub.ts`, `stream.ts`), but eliminate ambient injection, direct execution bypasses and model-visible secret entry. Output scrubbing cannot prevent arbitrary authorized code from exfiltrating a secret.

## Recommended implementation order

1. **Contract/safety foundation, narrowly scoped.** Version Session metadata/entry/result/capability schemas with runner and Apple/Android owners. Name durable authorities, supported operations, stable ID maps, policy-before-resume, publication/resync and receipt semantics. Finish the existing safety/import lanes rather than adding unguarded providers. Shared fixture suite may grow incrementally; do not block an unrelated personal Mac attach path on a rewrite.
2. **Daily-use essentials.** Persistent names + explicit rename + optional background naming; introspection; transactional todos; capability discovery; content selection. Include byte/attachment limits in tool/media output. Each feature needs a usable headless semantic surface before client-specific rendering. Reuse existing pure code only where its contract actually matches.
3. **Context and convenience.** Authorized extra context files; scoped history search/read/grep; mmry; draft stash and exports; trx picker backed by real semantic issue operations. These provide high value without duplicating orchestration. No history/memory direct-store bypasses.
4. **Managed orchestration and revisions.** Native subagent ownership/cancel/reporting; branch/fork/reviewed conversation edits; workflow intent and then separately admitted recurrence. Reuse Durable primitives and version-specific fixtures; generated privileged code is not a substitute for a provider.
5. **Optional high-risk/platform features.** Narrow secret-use provider and authenticated share inbox; SSH/sudo only after protected host credentials, remote identity, descendant teardown and uncertainty are proven. Kompressor after retention/source/recovery evaluation. Keep host-specific terminal controls separate throughout.

This is a priority recommendation, not authorization to implement every phase, change archived status or switch the live runtime.

## Acceptance checklist for each selected port

- Source/version recorded; a single semantic owner; classic Pi remains unaffected. No fallback to the legacy loader to fill missing APIs.
- JSON-schema/structured-output/error contract validated, with bounded/paged data and no secret-bearing diagnostic paths. UTF-8 limits cover model, structured program output, progress and stored details.
- Stable Session/conversation/task/call/entry IDs remain distinct; changed-payload request-ID reuse rejected; two clients cannot double-decide or erase newer state. No matching by text/index/count/display order.
- Intent/result recovery tests before/after side effect, commit and acknowledgement; explicit safe/unsafe/unknown disposition. Revoke/expiry/cancel/failed teardown cover progress and final disclosure, not just start permission.
- Session switch, branch/fork, client detach/reconnect and process reopen; state scope and inheritance explicit. Imported archives never grant credentials/permissions or schedule work.
- Provider-denied cases prove **zero provider/effect calls**, not just an error message. Secret use, model disclosure, file access and remote execution have independent scopes.
- Node, Apple and Android consume shared language-neutral golden fixtures for supported semantics; unsupported adapters return explicit typed unavailability. Native lifecycle, OS permission/revocation, credential login and actual rendering/device tests remain separate evidence.
- No whole-suite readiness claim from the 57 pure core tests or a mock UI. Full runtime, authenticated runner/Account, real provider, native hardware/lifecycle, external-effect and release/deployment qualification remain unproven by this audit.
