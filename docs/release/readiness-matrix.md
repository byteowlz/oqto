## Native Windows diagnostic (not release acceptance)

Using the operator-confirmed ED25519 fingerprint `SHA256:bmCmjueoy0DAyQy4y3kLOQX1sCGmQjqAa5UNk7EPZ+s`, an isolated Windows 11 MSVC checkout of `feat/install-matrix-safety` at `6c5c221f` ran `cargo test --locked` for `oqto-protocol` (47 passed) and `oqto-provisioning` (6 passed). `oqto-setup` fails to compile on native Windows because release activation/extraction require `std::os::unix::fs::PermissionsExt`, `symlink`, `mode`/`from_mode`. Placement/runner builds reach `oqto-sandbox`, which fails on Unix `getpwnam`, `geteuid`, `flock`, fd and missing Windows `exec_direct`. Separately, a SHA-256-verified tracked-source snapshot of Desktop `feat/personal-runner-client` at `68b4a3c` compiled/tested compositor (31 passed), design (8 passed), and `cargo check -p oqto-workdir`; `oqto-pi-client` fails on `std::os::unix::net::UnixStream`, Desktop's pinned Oqto `oqto-sandbox` dependency fails on Unix syscalls, and a workdir symlink test is Unix-only. Windows Rust 1.98.1 MSVC and Git 2.55.0 are present, but only rustc/rust-std/cargo components are installed; native Clippy and rustfmt cannot run without modifying the VM's user-owned rustup toolchain. Logs are under `C:\\Users\\admin\\oqto-native-logs`; checkouts and source snapshot are private to that VM. No Windows Oqto installer, service, GUI, Pi credential, RDP or overlay setting was changed. These compile failures are blockers to a native Windows release—not a reason to silently downgrade sandbox policy or claim Desktop acceptance.

## Required before calling it a release

1. Close `oqto-vemr.9.1` and children `.9.1.1`–`.9.1.3`: provide a complete, signed, version-coherent **full** Linux artifact with frontend/backend units and a separately declared **runner-only** target without those assets. Both must have the appropriate supervisor transport, working Pi chat with a usable model/provider, preserve-first user configuration and strict target-specific doctor proof. First personal install must offer user-consented native Pi Codex/ChatGPT OAuth or another usable provider; EAVS is optional when direct Pi authentication is chosen. Runner-only does not imply chat-optional. Fresh full personal **and** team hosts remain separate gates.
2. Close `oqto-vemr.8` and `.9`: make published artifacts match the canonical manifest/installer, exercise fresh/update/rollback/uninstall and dependency installation from artifacts rather than source. Test both profiles on independently reset hosts. Treat the snapshot/`--disposable-vm` choice as operator authorization, not verification of a hypervisor snapshot.
3. Prove runner sandbox policy, effective host/supervisor capability probing (`oqto-nppq.12`), Files placement/race gates, session identity/revocation and durable reconnect before broad remote-client enrollment. The Podman supervisor checks effective `podman info` rootless status before creating directories/pods. Its read-only, expiring capability report captures effective rootless state and engine version from the **same** `podman info` call; malformed/missing versions fail closed before host mutation. It keeps discovery separate from container launch, runner sandbox, and operator policy; any missing/denied/stale gate prevents availability (15 placement unit tests, including unavailable-engine privacy/no-mutation denial). `PlacementSpec` now rejects option-shaped images and ambiguous/traversing Podman bind sources (workspace, state, Unix socket and TLS files) before running the engine or creating directories; its image/volume regression went red before the fix and green afterward. This is input safety, **not** host-root authorization. `PlacementSpec` now also rejects every nonempty inline environment map (including innocuous-looking `AUTH_HEADER`) until a typed secret provider exists; Podman argv never contains `--env`. Red/green regressions prove denial before engine or directory mutation without printing values (`oqto-nppq.12.1`). Native disposable Ubuntu 22.04 placement gates passed with 15 unit tests, two image-dependent tests **ignored**, unrestricted Clippy `-D warnings` and fmt. No service or installed release was changed. On the disposable Ubuntu VM, the read-only combined probe returned `true 3.4.4`; rootless `podman info` reported `true` and a separately authorized isolated-HOME/XDG, `--network=none --read-only --cap-drop=all` BusyBox container launched and exited successfully (`~/oqto-release-e2e/podman-rootless-canary.log`). This is **generic rootless Podman launch proof**, not a runner-image/Workspace pod proof, and it does **not** establish usable `/dev/kvm`, Docker or Kata readiness **on that Ubuntu installation**. Historical native proof exists on the Arch workstation: Kata 4.0.0 launched a guest through containerd/`ctr` with Cloud Hypervisor, completed five cold-cycle timings and guest exec tests (`oqto_refactor/docs/spikes/20260805-hypeman-microvm-spike.md`). The same spike found Podman 6.0.0 → Kata 4.0.0 runtime wiring failed; historical `ctr` proof is not proof of the current Podman supervisor integration or Ubuntu host capability. Unrestricted `cargo clippy -p oqto-placement --all-targets --offline -- -D warnings` now passes: `oqto-jrf6` boxed an internal stdout-subscription error response with regression tests for missing/non-RPC/no-channel responses and buffered/live replay. Runner (81 tests) and placement (15 tests) passed; no warning suppression. A binary on PATH or `/dev/kvm` alone does not prove runnable isolation; never downgrade multi-user placement silently. Enforce the organization SSO/MFA gate `oqto-v6hw` for Desktop, headless and WebUI human access; Pi provider OAuth, EAVS and a private overlay are not Oqto Account authentication. Tailscale, Headscale and NetBird are optional connectivity recommendations (`oqto-qdxv`), not shipped dependencies or grants. Keep Mac Studio live runner unchanged without explicit operator grant.
4. Run clean native macOS and Windows GUI/install/update/uninstall tests on VMs, including distribution signing/Gatekeeper for macOS and native Windows packaging. No VM evidence means **blocked**, not passed.
