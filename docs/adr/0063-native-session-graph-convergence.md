# Native Session Tree convergence preserves provenance and requires head evidence

Personal Runner observation needs native Branch changes to converge even when message counts and file size do not change. Retain ADR-0025's single background ingest writer and read-only chat paths, but use actual native entry ids, parent links and a head reported by the attached native runtime—not counts, text, last-line position or a reading bookmark.

The native graph projection is a separately identified source/Branch inside the existing oqto-log store. Retain legacy turns, messages and Fork provenance; never destructively replace them to adopt a native graph. Raw native envelopes preserve all entry types. Repeated source ids must retain identical payload and parent facts; mismatches fail closed. Canonical reads select the explicitly evidenced native head and its ancestor path, retaining sibling branches durably. A missing/unsupported head is unavailable, not permission to guess. Observation and reconnect may nudge the serialized writer, but must never synchronously import, select a native Branch, replay input or start another Pi.

This deliberately costs a distinct provenance-preserving projection for legacy Sessions rather than rewriting committed canonical identities. Qualification must cover equal-count head switches, non-message ancestors, repeated content with distinct source ids, immutable-source mismatches, partial source tails, read-only reload and no duplicate Pi.

## Global identity inventory and readiness

Identity discovery must not retain one SQLite worker per canonical shard. Native identity reads and canonical catalogs share two process-lifetime reader connections, with one exact read-only shard attachment per borrowed connection and cancellation cleanup before reuse. SQLx pool capacity is not a physical-worker bound across cancelled acquisition. Each fixed reader is established once on a caller-independent initializer thread/runtime; synchronous lease return retains the same connection even when a caller runtime shuts down. There is no worker replacement/recycling path. Initialization or irrecoverable worker failure fails closed for that slot until process restart; shard/attachment faults can recover on the same readers after successful cleanup. Canonical metadata enumeration and source-header/default-name snapshots each have a separate single blocking-scan permit, retained across caller cancellation. These bounds are independent of shard/HOME/validator count; other existing Runner databases and the one destination writer remain separate.

Global checks strictly enumerate every shard and retain old schema facts without reader migrations. No ownership/schema answers are cached; prepared requests contain no identity facts and commit rereads current global authority. A missing/unreadable shard, failed probe or failed post-write verification invalidates the entire batch, never removes a shard and continues. Recovery requires a new complete probe. New/upgraded shards participate through fresh enumeration, not destructive inventory refresh.

Initial inventory/preflight work is read-only and polled beside native observations; only the existing serialized writer commits a header or merges a graph. A prepared request is restarted after intervening writer work. Explicit readiness distinguishes initial Checking, normal partial Discovering and failed/poisoned authority. Failure immediately fences cached catalogs and session actions through existing unavailable semantics, while cleanup remains usable. Complete generation-fenced retries may restore readiness; transport liveness/capability support is not authority readiness. Strict capability/enrollment wire shapes stay unchanged.
