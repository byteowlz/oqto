# ADR-0056: Deploy is one root transaction; history backfill is a separate one

Status: accepted (user-approved deployment hardening, 2026-10-09). Implements the ADR-0018 direction for `scripts/deploy.sh`.

`just deploy` used to build from whatever checkout it ran in, name artifacts by timestamp, let `oqto-setup install` advance `last-good`, and only *then* run history migration, a standalone Pi refresh, mmry migration, restarts and health checks — outside the installer's rollback. History migration quiesced writers with `pkill` across every user, ran as the deploying account inside other homes, and an "auto-heal" moved corrupt-looking oqto-log shards aside and deleted the backup after a rebuild. A dirty tree or an older checkout could replace a qualified release, and a failed gate left a broken release marked good (oqto-q9sp.6.1).

We decided:

- **Releases are identified, not timestamped.** `package.sh` packages only the declared Cargo version, refuses dirty or untracked worktrees (an explicit `OQTO_DIST_ALLOW_DIRTY=1` build is recorded as dirty), and writes `release.version`, `source_commit` and `source_dirty` into the staged manifest. `oqto-setup install` refuses, before extraction or before activation, any artifact whose name and manifest versions disagree, that lacks provenance, that was built dirty, or that is not strictly newer than the active release. `--allow-downgrade` and `--allow-dirty-source` are the only, explicit, audited overrides; an active release with no verifiable version also needs `--allow-downgrade`.
- **Activation is one root transaction on the target** (`scripts/dist/deploy-transaction.py activate`). It inventories every principal that owns a live managed runner socket (not a username prefix), refuses while sessions are busy, stops services, takes coherent byte snapshots of platform SQLite and configs without opening them, and runs `oqto-setup install` with its own `check` as `--post-activate-check`. The check restarts usermgr → runners → control plane and proves backend health *at the new version*, that every runner executes the new release binary, the bundled Pi version and (personal) the strict doctor — all before `last-good` moves. A failed check is rolled back by `oqto-setup`; the transaction then restarts the previous services. Snapshots are retained, never auto-restored.
- **The Pi runtime comes from the release** (ADR-0054). Deploy no longer installs the standalone Pi; it only points a *managed* `/usr/local/bin/pi` at `releases/current/...`, preserving unmanaged entrypoints. Pinned extensions are still synced, preserve-first: replaced or retired managed extensions move to a timestamped per-user backup, unchanged ones are untouched.
- **History is never part of activation.** `--backfill` (after activation) or `--backfill-only` (no binary change) runs `deploy-transaction.py backfill`: per principal it refuses foreign-owned or symlinked store entries, stops only that principal's writers (and the personal backend, which reads the store), snapshots the oqto-log store, runs only `sync-identities | bootstrap | validate | validate-changed` *as the owner*, fails if Pi JSONL changed, and on any failure keeps the failed state for diagnosis and restores the exact snapshot. Pi JSONL is never written. The destructive auto-heal, deploy-time mmry migration and `pkill` quiescing are deleted.
- **Partial deploys are gone.** `--skip-build/--skip-frontend/--skip-backend/--skip-services/--prepare-only/--activate-only/--resume/--allow-legacy-path/--remote-build/--trace-streams` and `scripts/deploy-binaries.sh` were removed: every deployment is one complete, verified artifact.

## Consequences

- Deploy is slower to *start* (a full release build from a clean tree) but cannot silently regress a host; prebuilt artifacts still deploy with `--artifact/--checksum`.
- Tools older than their pin fail preflight with the acquisition command instead of being reacquired as a whole set, which could have downgraded newer installed tools.
- Sidebars no longer refresh from a deploy-time identity sync; runners converge in the background or an operator runs `just deploy-backfill <host>`.
- Release activation still does not install policy assets such as the seccomp BPF; preflight fails closed when enforcement is configured without one.
