# Runner-mediated Files discovery (review slice)

`FilesWsCommand::Search` and `Preview` use the authenticated Files channel, but **do not** use the legacy host-bound `RunnerUserPlane` or unrestricted `ReadFile`. The backend requires an exact Account-scoped Session work-directory path and checks shared membership independently of placement. Local requests also pass the existing workspace validator. Remote requests require an active Account-scoped WorkspaceLocation (`kind != local`, path matches), a live PlacementRecord for its `workspace_id`, a matching `runner_id == PlacementRecord.id`, and appropriate Account/shared Workspace identity. An active remote location whose placement is revoked or mismatched fails closed. A missing/inactive location is not yet durably distinguishable from a never-remote local Session: if the same path exists on the backend host, local resolution can still succeed. Bind discovery to a stable Work-directory/location identity and test this case before merge. The runner requires that the requested root canonicalize beneath its trusted `local.workspace_dir` config; deployments must set this to the directory containing their mounted Work directories. The caller supplies only a relative child path. No backend-host or desktop filesystem search is performed.

Name mode executes `fd --print0` to bounded input then `fzf --read0 --print0 --filter`; content mode executes `rg --json --fixed-strings --no-config --max-filesize 2M --max-count 8`. Both run on the owning runner without a shell. Default ignore/hidden behavior applies; `include_hidden` opts into hidden files without disabling ignore files. Each request permits at most two concurrent runner searches/previews, 5 seconds total (including semaphore wait), 256 query bytes, 1 MiB `fd` output, 256 KiB tool output, 100 returned matches, 1024-byte relative result paths and 240-character snippets. The entire search fails explicitly if a tool is missing, exceeds its output cap, or times out; cancellation drops/kills child processes. Non-UTF8 path identities are skipped, not decoded lossily. Name hits include directories (`is_dir`); content hits are files only.

Preview is a separate contract: offset <= 1 GiB, limit 1..16 KiB, optional expected version <= 128 bytes, metadata/version returned, text extension allowlist only, bounded seek/take (never whole-file read). On a first selection use `expected_version: null`; on subsequent reads pass the returned version. A stale version fails rather than showing content. Unsupported media/PDF/binary types return metadata plus `unavailable`, never the original media. The client must reject responses for a superseded selection/request ID. A range ending inside a UTF-8 code point currently returns `unavailable` rather than the valid text prefix; align or trim partial text at the byte cap before treating remote text previews as polished. `FilesWsCommand::Read` is unchanged and must **not** be used as preview: it currently reads whole files before slicing.

This is **not** a release of complete remote Files. Current branch has path-addressed Session and WorkspaceLocation records, not ADR-0032's stable work-directory IDs or ADR-0038's complete runner Gate/registration grants. A Work directory without a Session, a remote location lacking an exact runner placement ID, or a container root outside the configured runner workspace root fails closed. No thumbnail/derivative cache, PDF/video/audio preview, client integration in oqto-desktop, watcher snapshot/replay, or full remote Files navigator is implemented here. Canonical containment and post-open version/path rechecks prevent ordinary traversal and symlink escapes but not all concurrent symlink/directory replacement races; hardened fd-relative `openat2`/no-follow access remains necessary before treating this as an isolation boundary against a malicious local Principal. The legacy unrestricted `ReadFile` route is not made safe by this change. Transport-identity and registration revocation guarantees remain subject to ADR-0024's unfinished conformance work. Do not market the slice as a fully secured remote Files deployment.

Verification on Linux: `cargo check -p oqto-runner -p oqto`, `cargo test -p oqto-runner file_discovery`, `cargo test -p oqto --lib fake_remote_`, `cargo clippy -p oqto-runner --all-targets -- -D warnings`, and `cargo clippy -p oqto -- -D warnings`. Tests cover sparse GiB preview byte cap, stale version, traversal/symlink denial, odd filenames, missing tools, cancellation, hidden files, directory hits, two-slot concurrency, and fake remote endpoint/placement identity. Full WebSocket/revocation integration and native-client selection-generation tests remain to be added before production rollout.
